# Где храним отчёты Метрики, Директа и SEO

Дата регламента: 21.08.2026  
Ответственный за утверждение: Виталий  
Основной домен: `kronotech.ru`

## Один показатель — четыре уровня хранения

| Уровень | Где | Формат | Для чего |
|---|---|---|---|
| Сырой источник | `raw-exports/` | JSON; при табличных данных также CSV | Повторная проверка и аудит без нового запроса к API |
| Проверенная история | `Кронотэк-Маркетинг.xlsx` | XLSX, только нормализованные показатели | Единый источник правды по динамике |
| Вывод и решения | `консультации/` | Markdown + автоматически созданный HTML | Объяснение причин, рисков и следующих действий |
| Текущий обзор | `index.html` | Сгенерированный дашборд | Быстро посмотреть актуальное состояние; вручную не редактировать |

## Яндекс Директ

Сырые ответы API сохраняем без ручных исправлений:

- `raw-exports/direct/direct-YYYY-MM-DD--YYYY-MM-DD-raw.json` — полный ответ;
- `raw-exports/direct/direct-YYYY-MM-DD--YYYY-MM-DD-normalized.json` — приведённые поля для расчётов;
- при необходимости детализации по запросам — CSV с тем же диапазоном дат.

В книгу записываем только проверенные показатели периода: расход, показы, клики, CTR, CPC, заявки, качественные заявки, CPL и CPA. Ставки и бюджеты не изменяем через отчётный процесс.

## Яндекс Метрика

Сырые ответы и длинные таблицы сохраняем отдельно:

- `raw-exports/metrika/metrika-<тип>-YYYY-MM-DD--YYYY-MM-DD-raw.json`;
- `raw-exports/metrika/metrika-<тип>-YYYY-MM-DD--YYYY-MM-DD.csv` — строки для ручной проверки;
- `<тип>`: `traffic`, `conversions`, `sources`, `404` или другой понятный вид отчёта.

В книгу записываем агрегаты по дням или неделям: визиты, органический трафик, заявки, качественные заявки, конверсию и согласованные цели. Сырые URL, User-Agent и тысячи строк в книгу не переносим.

## SEO

История хранится на листе `Поиск-история` книги. На 21.08.2026:

- поле средней позиции выведено в SEO, но значение пока намеренно не заполнено;
- страниц сайта: `495` уникальных URL в `sitemap.xml`.

Важно: количество страниц означает уникальные URL карты сайта, а не количество материалов Drupal. В файле было 497 строк и 2 дубля.

## Имена и неизменность данных

1. В имени каждого файла указываем источник, тип отчёта и период данных.
2. Сырой файл после сохранения не редактируем; исправленная версия получает новое имя.
3. В книге старые строки не переписываем — добавляем новый срез с датой.
4. В отчёте обязательно пишем источник, период, ограничения и принятые решения.
5. Пароли, токены API и SSH-ключи в файлы проекта не записываем.

## Что не стоит делать

- Не использовать Google Docs или PDF как единственный источник цифр: их трудно проверять и обновлять.
- Не складывать сырые выгрузки на листы книги — файл быстро станет тяжёлым и неудобным.
- Не править `index.html` вручную: он пересоздаётся из книги командой `python dashboard_gen.py`.

## Рекомендуемый рабочий цикл

`API/выгрузка → raw-exports → проверка → дописывание в XLSX → вывод в консультации → пересборка дашборда`.
